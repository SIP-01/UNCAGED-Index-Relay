## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| UIR-M1 | MEDIUM | src/relay.ts (REQ/COUNT handling) | No per-IP REQ rate limit (verified in source; `.env.example` exposes no such knob). An attacker can open N connections × 20 subscriptions and issue unbounded expensive REQ/COUNT scans against OpenSearch — CPU/IO amplification DoS. Sister project SIP-Booster-Relay already has token buckets (`REQ_RATE_LIMIT` 50/min) — port that pattern | Add per-IP token bucket for REQ/COUNT/NEG-OPEN (IP_HEADER plumbing already exists), plus a per-IP connection cap |
| UIR-L1 | LOW | src/server.ts `/metrics` | Prometheus metrics endpoint publicly exposed with no auth (per-IP traffic counters, queue depths) | Bind to localhost or gate behind a token/IP allowlist |
| UIR-L2 | LOW | docker-entrypoint.sh | Auto-generated relay nsec is printed to container logs once (by design, but logs are often shipped to aggregators) | Print only the npub; write nsec solely to the chmod-600 file |
| UIR-L3 | LOW | repo | GHAS secret scanning not enabled; no SECURITY.md | Enable scanning; add SECURITY.md |
