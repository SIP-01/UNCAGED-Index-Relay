# Improvement Deep-Dive — UNCAGED-Index-Relay — 2026-10-21

Companion to AUDIT-2026-10-21.md. Focus: what to change/update/improve, grounded in files read on `main`.

## Top recommendations (ranked, with effort S/M/L)

1. **[M] Port SIP-Booster's per-IP / per-pubkey token-bucket rate limiting.** This relay has NO message rate limiting — only a subscription-count cap (`src/relay.ts:1415` "rate-limited: too many subscriptions") and a per-connection EVENT-dispatch semaphore (`src/relay.ts:454`). A single client can flood EVENT/REQ unthrottled. The mechanism to copy already exists in the sibling repo — see "Port plan" below.
2. **[S] Add GitHub Actions CI.** The only CI is `.gitlab-ci.yml` (biome + typecheck + bun test) but the canonical repo lives on GitHub — nothing gates PRs here. Port the 4-line pipeline (biome ci --error-on-warnings, tsc --noEmit, bun test) to `.github/workflows/test.yml`.
3. **[S] Add a secret-scanning gate (gitleaks action).** Repo is a relay that operators configure with keys via env; a committed `.env` would be caught by nothing today.
4. **[S] Enable branch protection on `main`** (require PR + status checks). All branches are currently unprotected.
5. **[S] Dependency freshening** — see below; `nostr-tools` and `zod` are behind verified latest.

## Port plan: SIP-Booster per-IP token bucket → this repo

Source mechanism (SIP-01/SIP-Booster-Relay):
- `src/types.ts:140-168` — `RateLimiter` class: token bucket, `removeToken()` + time-based `refill()`. ~30 lines, zero deps, directly portable.
- `src/config.ts:62-65` — `SIP01_INDEXER_RATE_LIMIT = { rate: 120/60000, capacity: 240 }` (roomier bucket for kind-39697 indexer bursts).
- `src/config.ts:364-365` — `PUBKEY_RATE_LIMIT` (10 EVENT/min), `REQ_RATE_LIMIT` (50 REQ/min).
- `src/durable-object.ts:586-604` (`createSession`) — one bucket set per WebSocket session.
- `src/durable-object.ts:108` + `:1255-1263` (`takeNegOpenBudget`, `negIpBuckets` map) — the **per-IP** layer: budget keyed on `session.ip` so reconnects don't reset the allowance.

Target wiring in this repo:
- Client IP is already captured: `src/server.ts:171-172` (`config.ipHeader` fallback to `server.requestIP(req)`) and passed into the pool at `src/server.ts:268` (`pool.open(ws.data.connId, ws.data.ip, ...)`); it lands on the connection at `src/relay.ts:274` (`ip: init?.ip`).
- Add the `RateLimiter` class (copy from `src/types.ts` in SIP-Booster, it's MIT-licensed sibling code) into `src/relay.ts` or a new `src/rate-limit.ts`, with tests next to `src/config.test.ts`.
- Enforce in `handleEventMessage` (`src/relay.ts:812`) — reject with `OK false "rate-limited: ..."`; and in the REQ handler (`src/relay.ts:1340`, where "invalid: too many filters" is already emitted) — `CLOSED "rate-limited: ..."`.
- Give kind 39697 writers the roomier bucket (same 240-cap/120-per-10-min profile as SIP-Booster) so Crawlstr/indexstr bursts aren't choked.
- Keep buckets in a `Map<ip, RateLimiter>` with TTL eviction (mirror `negIpBuckets`' `{count, resetAt}` pattern) to bound memory.
- Expose knobs in `.env.example` following the existing `RELAY_MAX_LIMIT` style: `RELAY_EVENT_RATE_PER_MIN`, `RELAY_REQ_RATE_PER_MIN`, `RELAY_SIP01_BURST_CAPACITY`.

## Ecosystem alignment notes

- NIP-86 relay-management API is the 2026 standard for relay admin (banpubkey/unbanpubkey, allow/unallow, blockip, claims, delegated method grants). Neither this relay nor SIP-Booster implements it (SIP-Booster NIP-11 advertises `[1,5,9,11,16,33,42,45,50,77]`). Adding NIP-86 here would let SIP-dashboard become the admin UI (see that repo's report). Effort M/L.
